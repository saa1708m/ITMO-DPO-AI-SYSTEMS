# Модуль 7. Мониторинг и наблюдаемость ML-систем

## Датасет

В исходнике собраны 15-минутные измерения промышленного энергопотребления за 2018 год. Итоговый файл содержит два реальных сезонных окна одинакового размера: январь–март как `reference`, июль–сентябрь как `current`. Такое разделение позволяет искать естественные изменения распределений, не добавляя искусственный drift.

## Учебное применение

Для лабораторной 7.2 студент сравнивает окна с помощью PSI, KS-теста или отчёта Evidently, отделяет статистически заметный сдвиг от эксплуатационно значимого и формулирует правило алерта. В лабораторной 7.1 тот же поток можно подавать в сервис батчами и собирать метрики числа запросов, latency, долей `load_type` и распределения `usage_kwh`.

Практическое задание: построить reference/current-отчёт по энергопотреблению и коэффициентам мощности, выбрать пороги алертов и объяснить, какие сигналы требуют переобучения, а какие — только наблюдения.

## Столбцы


| Столбцы                                                        | Содержание                                          |
| -------------------------------------------------------------- | --------------------------------------------------- |
| `timestamp`                                                    | 15-минутная временная отметка в ISO 8601            |
| `period`                                                       | Учебное окно: `reference` или `current`             |
| `month`, `hour`, `minute`, `is_weekend`                        | Производные календарные признаки                    |
| `usage_kwh`                                                    | Потребление активной энергии, кВт·ч                 |
| `lagging_reactive_power_kvarh`, `leading_reactive_power_kvarh` | Реактивная энергия                                  |
| `co2_tonnes`                                                   | Расчётный показатель выбросов CO₂ из исходника      |
| `lagging_power_factor_pct`, `leading_power_factor_pct`         | Коэффициенты мощности, %                            |
| `load_type`                                                    | Категория нагрузки: `light`, `medium` или `maximum` |


## Выполненные преобразования

Дата приведена к ISO 8601; исходные `NSM`, `WeekStatus` и `Day_of_week` заменены однозначными календарными признаками; поля и категории переименованы. Для каждого окна выполнена воспроизводимая стратифицированная выборка по `load_type`: по 7 500 строк, `random seed = 42`. В reference-окне осталось 3 903/2 055/1 542 наблюдения классов light/medium/maximum, в current-окне — 3 933/2 038/1 529. Строки в итоговом файле отсортированы по времени.

Синтетические строки, пропуски и выбросы не добавлялись. Различия окон происходят только из реальных наблюдений разных сезонов.
